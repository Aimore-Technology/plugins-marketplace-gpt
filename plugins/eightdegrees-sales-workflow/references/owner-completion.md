# Complete from API acknowledgements

Use [API results/minimal reads](api-result-policy.md) and the generated
[execution plan](execution-preflight.md). This applies to all workflow owners.
Notion, CRM, Gmail drafts and preview publications use original successful
responses/record IDs. No post-write body, downloaded asset or hash comparison.

Freeze affected roles, versions and this phase's obligations before work. Keep
one current ResumeStep per plan. Preserve current approvals, stop/window/count,
source/recipient/attempt checks before the actual external action. A ContentReview
phase cannot require future Sent/CRM receipt/SMS outcomes. A provider action
must not repeat because a later internal projection/log failed.

For each successful write, run write.confirm and retain its APIWriteConfirmed
result. Use service/purpose/entity/content_version from the generated spec.
Reuse the current pre-call route result; sending additionally retains the
original provider.handoff result and notification SMS authority. These prove
our request was accepted, not transport/delivery. Actual CRM writes need a
NoteId acknowledgement; draft preparation cannot substitute for a send.

completion-gate uses frozen required_checks, invocation_id, publication_version
and actual integer exit/results. owner-write checks registered target/policy,
scheduled guard if applicable, current versions/route, and receipt coverage
before allowing final metadata. report-write keeps its narrower report scope;
report cannot perform business actions. No body fetch is needed after final
Completed/Success; confirm that write's original API response and save its ID.

Record partial failure honestly. Unknown attempts are reconciled by original
identity before retry; already acknowledged effects remain complete. Missing
CRM receipt or material follow-up registration repairs only that phase, never
another email. One record's failure does not block unrelated work.

Reuse initialized IDs/schemas/templates across cycles, and original successful
captures across local checks. Refresh live operator submissions/approvals and
stops for affected actions. Full audits are explicit diagnostics, not normal
completion work. Old strict execution-v1/v2 contracts remain historical; use a
linked execution-api-v1 plan for new unfinished phases without replaying effects.
