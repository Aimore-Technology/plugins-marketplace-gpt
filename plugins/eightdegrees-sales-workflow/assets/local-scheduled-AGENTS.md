# EightDegrees native heartbeat entry

Apply this section only to actual EightDegrees scheduled wakes in this working
directory. Ordinary user commands retain their own command boundaries.

On EVERY native wake resolve the current installed EightDegrees resource from
the host's enabled plugin catalog or its previously verified unversioned
source.path. Read scripts/current_rules.py there afresh and read the returned
current scheduled entry, scanner and guard. Enter email-scanning directly under
scheduled-approved-work; do not route through public run-auto or start/stop.
Do not repeat marketplace upgrades or management discovery every tick. Resolve
a moved resource through supported host listing when necessary; listing itself
is not a native execution prerequisite. Retain the actual rule version/hash,
not an old version path or historical chat instruction.

Read original registered Notion RunSettings first. Stop/revocation is effective;
native task ACTIVE metadata cannot enable scanning. Old executor/chat binding,
native_runtime_verified, host identity, global serialization or missing native
management APIs cannot block an otherwise passing current guard. Record any
real guard failure verbatim with its current evidence.

Existing EventIndex pending mail is executable demand even with no new mail or
index edits. Use backlog.recover over actual source/task captures and preserve
the original source/task/provider attempt. Repair saved-source handoffs through
RecoverSourceHandoff before new intake; save/read back intake and successor
pointers, then continue matching, project parsing and draft preparation to the
actual review/missing-information boundary. No continue command or duplicate
sources. Derive baseline completion from actual mail/actions/control/scheduled/
recovery and necessary source observations; never fake coverage or globally
block independent work on NeedsBaseline. Only sending waits for its window.

Use cycle.metrics with actual receipts, clocks, concrete blockers and next
pointers. Record loaded rule version/hash, timer trigger, guard pass and business
progress separately. Ready/no-progress must not be silently reported as idle.
Preserve precise email/CRM approval and standing SMS notification safeguards;
accepted/unknown external attempts cannot be resent. Resume one current cycle
after restart, not every missed interval. Never create/clone/modify a timer here.
