# Process customer communication

Read [operating-contract](../../references/operating-contract.md) and [notion-model](../../references/notion-model.md). Default Mode=Manual for the operator's P0-A request. Only an explicit upstream automatic workflow may supply Mode=Automatic for a separate new item; it cannot adopt an existing Manual task.

1. Save/reuse a source-linked Inbox record for the authorized email, text or transcript. Record account, original time/timezone and immutable SourceKey/CommunicationId; keep source and derived notes distinct. Link raw Gmail/Dropbox content rather than mirroring it. Mail-derived facts require readable source text; follow [mail decoding](../../references/mail-decoding.md) for corrupted bodies before matching or drafting. Sensitive originals follow manual handling.
2. Match within the configured CRM LocationId using email/phone; use names/social profiles only as supporting data. Ambiguity, absence or conflict becomes ClientMatching with exact candidates/missing input and original source. The operator selects or supplies data; no guessing or automatic contact creation. Manual mode waits for an explicit continue request after saving.
3. On verified mapping, resolve/reuse the customer page by LocationId + ContactId and registered page ID. Use a human-readable CRM name for its title under `Clients/{ClientDisplayName}/Communications`, following [customer pages](../../references/client-pages.md); keep full IDs in metadata, never use the display title as identity. Move/link the source while retaining its original page identity. Before ContentReview, verify archival using [Notion I/O](../../references/notion-io.md). A failed link stays pending. Record mapping/state and a local timestamp + unique communication title suffix. Reuse valid upstream mapping instead of asking again.
4. Build the complete plain-text note with [CRM Notes](../../references/crm-notes.md): required audit header plus four fixed sections and supported persona proposals. Validate before ContentReview and save exact text/template/input/digest. Provide the current version's dedicated [action page](../../references/operator-actions.md) for review/revision comments and one submitted content decision; the operator never fills actor/version IDs. Changed text needs a new validated review version/page. Confirmation is not permission to send.
5. On explicit manual continue where required (original task or registered action URL), validate/record the submitted action decision or valid original legacy/chat evidence. Re-fetch active action inputs, original approved payload and CRM target/latest records; validate exact bytes/digest and completed writes. Incomplete legacy approvals require a corrected new review, never silent formatting or header additions. With NO persona changes append the approved plain text once. With changes pass that same complete payload and approved changes to [persona update](../eightdegrees-client-persona-update/SKILL.md), which owns ONE append. No duplicate prewrite; reconcile by CommunicationId + approved version. Only verified structured mappings may additionally change.
6. Read back actual CRM results; save the approved Notion note/persona snapshot and per-step sync status. Return target, external record IDs, confirmed version and task/run links. Partial failure or unknown state goes to ExecutionExceptions; manual mode waits for the operator's explicit retry/continue and reconciles before filling missing steps.

Finish only when source is traceable, customer verified, proposed changes approved, CRM result read back and Notion sync state consistent. This skill sends no customer email/SMS, starts no timer, calls no scanner, and never changes an existing Manual task's mode.
