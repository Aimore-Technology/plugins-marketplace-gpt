# Task results must come from tasks

A view labelled Recent results accidentally used WorkflowRuns. Completed
PendingTasks could never appear there. Keep a task_results view over the original
PendingTasks source, with Completed/Cancelled states and Result; keep runs as
separate history. Preserve existing native view IDs and register additions.

A checked legacy action submission can coexist with WaitingForOperator and a
false InputSubmitted compatibility projection. Observe the actual bound form
with task.submission, persist the request and project ReadyToValidate once.
This requests processing only. Actual data application, CRM facts or customer
sends require their original owner and scope; content-only Confirm is not send
approval. Never mark a genuine SMS registration failure complete for appearance.

Use existing captures and API acknowledgements. Repair only missing display
projections after an interrupted write; do not repeat the business action or
add another confirmation/continue command. Completed current steps and waiting
successors have separate states. Invalid/withdrawn requests restore needs-input
and clear the projected submitted flag without deleting answers or history.
