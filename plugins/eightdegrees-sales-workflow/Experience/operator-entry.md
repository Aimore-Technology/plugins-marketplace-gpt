# Keep the operator's task and next step visible

Trigger: explicit setup/upgrade, a revised review or a submitted input page.

Observed: a copied hub queue can diverge from canonical task/action bindings;
technical database properties obscure the real input; a saved checkbox can be
mistaken for acceptance or a running schedule.

Action: use the verified Today linked-view configuration and original action
links. Keep Actions/history and original execution-discovery views intact.
Update canonical fields and the changed action only; do not recopy queues in
linked-view mode. Show three review lines and changed fields, then full matching
material before decisions. Reuse only verified applicable values; keep drafts.
Explain request vs acceptance and offer the actual owner/scan continuation when
no verified native schedule exists. Preserve separate content/send decisions.

Verification: read back native view source/filter/show fields, layout and changed
pages; compare saved IDs, original inputs, frozen payload and business settings.
Use local operator and capture-batch checks. Native layout/view verification does
not prove visual rendering, lower live latency or installed-model compliance.

Evidence: the 0.1.21 UX maintenance on 2026-10-31 verified native linked lists,
hidden technical detail properties and one unchanged-content review layout.
Offline regressions cover mode-specific continuation, correction, pause,
expiry, unknown results, verified prefill and result/receipt separation.
