# Handover and recovery

Trigger: initial inquiry intake, result publication or an interrupted/compacted
active invocation. Reuse this card; do not load it on every no-change tick.

- Durable ReadMessageBody receipt first, sales preparation second. execution
  preparation requires original intake_handoff evidence; no post-hoc pass.
- Keep one current status/result/input section and the original action-binding.
  Exact mutations refuse dropped bindings and repeated live headings.
- Email results update canonical task bodies, actions and the original source.
  The source's final Processed marker follows full owner completion; never make
  that marker a prerequisite for its own presentation proof.
- Resolve a stale wait from the original terminal canonical task/version, never
  from prose. Preserve unknown attempts and all expired/stop/count constraints.
- After compaction, resume the pinned current command/executor/deadline. Read
  original effect receipts; do not become the test controller, create another
  invocation, message another Session or resend to repair a result page.
- A legacy run can get an exact generated summary-only pointer to its terminal
  task. Keep missing old metadata and failed history, without broad write bypass.
