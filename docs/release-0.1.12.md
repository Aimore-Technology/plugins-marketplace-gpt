# 0.1.12 Current task publication and bounded report repair

The joint 0.1.10/0.1.11 test exercised the five commands through 49 invocations: 61 passed, 14 failed observations, one waiting and seven untested. Several failed observations recovered during that test. The remaining release work concerns owner-driven presentation consistency, preview prerequisites and report invocation boundaries, not a new Portal or backend.

Each task owner now finishes state/version/action-binding transitions by synchronizing the canonical summary, active action status and the one current Actions queue, then verifying changed saved projections. Old queues/headings are historical and native children/input remain intact. Data-only forms do not ask for a nonexistent single-choice decision. A failed status projection repairs only that projection from durable evidence; provider actions are not repeated.

HTML review requires the actual saved native block and exact downloaded frozen bytes before either content or send review becomes actionable. Upload URI/hash/external rendering alone is insufficient. A missing prerequisite preserves copy/comments in a non-approvable draft. Old unusable review evidence stays historical; an explicit draft-owner invocation produces a fresh synchronized review version without releasing stop/Pause.

Report-only freezes actual report/run/log targets and checks each proposed mutation. Defects in tasks, action pages, previews, navigation or Health are findings for a separate owner invocation. They are not repaired as report children. Final actual mutations are audited against the same registry. This corrects the observed report43 boundary failure without claiming host enforcement from a Skill Pack.

New offline notion_checks.py plans exact workflow-owned H2 section patches, verifies saved native embed/download evidence and compares proposed/captured report writes to registered targets. It performs no I/O except reading captures/stdin and printing JSON, calls no connector and grants no approval. Stable file-block references require the original fetch mapping and exact downloaded embed bytes as well as the frozen HTML download. Image/PDF fallbacks require their separate actual render-source mapping; unsupported inputs do not pass by assumption. The existing link checker additionally examines bare pre-publication URLs to catch punctuation swallowing before Notion serializes them.

Current tool contracts drive DDL types, property representations, documented resource URIs and Dropbox argument names. Short error properties use plain text; diagnostics remain in body/log history. Snapshot reuse limits repeated reads, while decision/transition-dependent readbacks remain mandatory.
