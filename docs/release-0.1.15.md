# 0.1.15 Communication routing, stored replies and owner completion

Implement the three priority defects identified in the 0.1.13 review. Retain the 0.1.14 Experience library and update its implementation/acceptance status rather than erasing original failed observations.

Add CompleteCommunicationData, owned by communication with DataCompletion/ExecutionExceptions categories and draft effect. It validates/persists/applies scoped Notion/source facts only, followed by a separate Notes ContentReview/ReviewCommunication. It does not append CRM Notes or grant factual/send approval. Original Waiting routes are checked before form activation/consumption. Explicit upgrade repairs only evidenced open legacy tasks/bindings; completed historical results remain unchanged.

Use the current documented Gmail stored-draft mechanism to avoid direct reply quote insertion: create a reply draft, replace the complete MIME tree with update_draft while omitting reply_message_id, read back exact raw draft/body/headers, bind that object to review and send_draft for the same approved ID. The current connector contract states that payload replacement does not append quotes and send_draft sends the stored object. No invented switch or raw API is introduced. The offline reply_transport.py plans HTML-only updates and validates exact bytes, stored mapping/thread/headers and pre-send/sent readbacks, detecting any quote/newline or target drift. Multipart assets are refused by this helper until their separate full-tree verification is available; they are never dropped or silently downgraded.

Add owner completion profiles and owner-write preflight for all seven owners, with direct instructions at each Skill entry. It recomputes current gate evidence, requires frozen matching contracts and profile coverage, binds task versions/actions/routes to the actual owner/policy and requires pre-send stored-draft proof for email send completion. Report retains its narrower report-write. Child persona work returns to its parent owner; missing publication evidence never repeats external mutations. These are executable offline preflights available to a model, not host-enforced interception or a separate backend.

Owner fixtures cover all seven profiles, missing/shrunk/stale contracts, action/task versions, route policies and both pre-send/sent MIME evidence.
