# EightDegrees Sales Workflow 0.1.25

Fixes the linked review/send result gaps observed in the 0.1.24 controlled run.
Initial project-email completion now requires email-presentation evidence across
the original send task/action and its completed content review/action. Later
explicit customer receipt or a known stale view enters a separate automatic
RefreshEmailOutcome maintenance item; terminal business tasks are not reopened.
Only current Notion results change. Approved bytes, decisions, provider proof,
customer stop and original IDs remain; no send, CRM append or new approval occurs.

The offline email_presentation helper plans exact patches and verifies complete
saved pages against the original captures. Receipt mapping checks the actual
Gmail reply parties, thread, actual sent RFC parent and an owner-selected positive
quote. Existing embedded RunSettings outcomes receive a scoped exact-value patch while
all other settings remain unchanged. Human receipt remains independent of provider Delivered. Missing or
conflicting legacy evidence stays a scoped finding, never a guessed repair.

Final-response rendering now supplies actual clickable action/result/Today links.
Already accepted SMS requests display as pending external execution; future stop
is separate from cancellation of an existing request. Trusted is not live phone
execution, and this package adds no AndroidSync cancel or inbound tool.

Local capture batches now include exact Notion mutation, owner/report scope and
email presentation checks. --output retains full results/exact calls locally
while printing short summaries. Refused batches remove executable calls. New
report/read guidance focuses affected originals, compact indexes and coalesced
noncritical monitoring writes without removing fresh pre-action checks.

Validation: 340 offline tests, marketplace and ZIP checks in both editions;
actual authorized 0.1.24 page captures replayed locally with unchanged protected
content/fields and zero edits on a repeat. The captured-page replay performed no
Notion/provider writes. A 200 KB call stays intact in the saved batch result while
console output remains below 2 KB. These are offline results, not measured live
latency or new end-to-end/Beta acceptance. Native jobs and Claude runtime were
not exercised. The earlier real SMS request remains a separate external issue.
