# EightDegrees Sales Workflow 0.1.58

Internal registration, connector and state failures are system maintenance,
not operator homework. PendingTasks retains its original failure state and
evidence, with ResolutionOwner=System or Operator. Today attention requires an
Operator owner, a concrete RequiredInputs question and the real input route;
it shows that question beside the route. System and unclassified exceptions
remain in a registered Dashboard System Recovery view over the same records.
They do not enter the personal waiting list or generate a fill/review/run-again
prompt. Failure metrics and original recovery remain intact.

exception.presentation renders what happened, business impact, the next step
and the operator action or explicit No action required. For read-only system
pages, old execution history stays inside one closed native maintenance toggle,
with payloads readable to existing helpers. Operator input controls and child
records are protected. Human forms receive targeted summary updates only.
This presentation repair neither completes the business step nor grants retry
or sending permission. Unchanged presentation has no writes.

New v4 email rendering also returns technical_content with the unchanged
binding/package in a closed native toggle. The customer still reads the reply
and checks Consent in Today; no extra page, approval or dispatch check is added.

Regressions cover system versus actionable human classification, missing or
raw machine questions, protected controls/children, preserved recovery records,
idempotent presentation, no user rerun prompt and closed mail-record parsing.
Live Notion changes repair the Harbour display/classification only: its SMS
registration association fault remains unresolved and is not reported complete.
No external messages or native schedules are changed by this release work.
